# Voice-01 Implementation Plan

**Goal:** 实现按键语音或文本输入，经本地 ASR、Ollama、POI 候选和用户确认调用现有导航会话。

**Architecture:** 浏览器录音上传 FastAPI；可替换的本地 ASR 与 Ollama 适配器分别产生文本和严格验证的意图。服务端以本地 OSM 数据查询候选；浏览器展示并仅在用户确认后创建现有导航会话。

**Tech Stack:** FastAPI、Pydantic、httpx、TypeScript、MapLibre、Ollama；本地 ASR 引擎及模型需单独准备。

**Spec:** `docs/superpowers/specs/2026-10-28-voice-01-design.md`

## 全局约束

- WGS-84 坐标由本地地图提供，LLM 不生成坐标或自由 API 调用。
- 模型仅按用户授权下载至 Git 忽略目录，不调用收费服务；不修改 GPS 工作树。
- 先测试后实现；导航、回放和偏航行为不得回归。

## 执行顺序与验证

1. 明确本地 ASR 具体服务协议与可用模型，写失败测试后实现录音上传、空语音及服务不可用处理；不得把模拟识别当成真实演示。
2. 为 Ollama 适配器和严格意图模型写协议测试，覆盖无关输入、非法 JSON、缺字段、模型不可用及禁止坐标；实现文本解析接口。
3. 扩展 OSM 构建脚本导出停车场，测试点、面、未命名地点及确定性；服务端使用本地 POI 及地点候选实现名称/类别匹配，覆盖多候选和无候选。
4. 前端增加录音、文本回退、状态、候选与取消；测试权限拒绝、ASR 失败、取消不调用导航、确认调用现有会话和无法到达。
5. 对接 MapLibre 候选展示，验证已有导航、模拟回放和偏航测试；记录本地服务、地图生成及真实浏览器演示前提。

## 技术决策待解决

参考项目没有离线通用 ASR，现有环境亦未确认 ASR 引擎和模型。需要先识别本机已有能力或明确选定本地 ASR 部署协议；不能声称语音端到端验收完成。珠海 OSRM 尚未构建，新工作树还缺少 Git 忽略的地图数据。
